WanderWay guide

The big picture

WanderWay is an AI travel planner built on Salesforce. The AI talks to the traveler. Salesforce holds the facts (prices, seats, bookings). The AI is never allowed to guess a fact.

Think of a hospital

One booking, start to finish

1 SearchFlow finds active packages
2 RecommendPrompt template picks best fit
3 CheckApex: seats and price, returns departureId
4 VerifyFlow finds or creates the Contact
5 SummaryPrompt template shows the trip
6 ConfirmTraveler says “Confirm booking”
7 CreateApex books it: status In Process
Golden rule: Package_Departure__c is the single source of truth for seats (Total seats minus Booked seats). Never the PDF, never the AI’s memory.
Why “In Process”, not “Confirmed”? New bookings hold seats while staff review. Only the approval process may confirm. The agent must never say “confirmed” on its own.

The bug: why “Prompt Injection”?

What you saw

The traveler typed “November 11, 2026” (or “yes confirm”) and the agent replied “Sorry, I can’t assist with that request.” The trace showed Router → Prompt Injection.

What really happened

  1. Salesforce has a built-in guard topic called Prompt Injection. It is not in your script, but the router can still pick it.
  2. Your router used HyperClassifier, a fast sorter that mostly looks at the newest message alone.
  3. A bare date, “2 travelers” or “yes” has no clear intent on its own. No department matched, so it fell back to the guard.
  4. The trace’s “embedded instruction” explanation was written by the guard topic afterwards. Nobody attacked the agent.

Two smaller problems made it worse: the old router prompt was full of words like “malicious” and “injection”, and its if line was mis-indented so it probably never ran.

The fix

ChangeWhy it works
Removed model_config (HyperClassifier) from the routerThe default model reads the whole conversation, so “Nov 11” is understood as an answer
Router before_reasoning: if BookingFlowActive is True, go to Trip_Planning_BookingPlain code, no AI guessing, while a booking is in progress
Trip subagent sets the flag on entry; end_booking_flow clears itFlag is on during the booking, off when finished, abandoned, or topic changes
Short, neutral router promptNo injection vocabulary nudging the choice
One-line answer for a mentor: “The router had no memory of the conversation, so short replies matched nothing and fell into the safety topic. I gave it memory with a flag and moved it to a model that reads context.”

Honest note: this is inferred from the traces; Salesforce’s classifier internals aren’t visible.

Variables: the notebook

  • linked: filled automatically from the messaging session (EndUserId, ChannelType).
  • mutable: the agent writes to it during the chat (VerifiedCustomerId, TotalTripPrice).
  • Internal: hidden from the traveler.
  • Key ones: BookingFlowActive (mid-booking), AwaitingBookingConfirmation (summary shown, waiting for yes), SelectedDepartureId (the checked departure).

Three tricks inside an action

with numberOfTravelers = ...                      the AI fills this from the chat
with departureId = @variables.SelectedDepartureId   hard-wired, the AI cannot change it
set @variables.TotalTripPrice = @outputs.totalPrice  save the result into the notebook

Hard-wiring IDs is a security feature: the AI can’t invent a Contact or departure ID.

Safety locks before a booking exists

  1. Instructions: never book without an explicit yes after the summary.
  2. The AwaitingBookingConfirmation flag records that the summary was shown.
  3. require_user_confirmation: True on Create_Booking and Modify_or_Cancel_Booking.
  4. IDs are hard-wired from variables.
  5. Apex re-checks everything and rolls back on error.
Be honest about identity: Verify_Traveller finds or creates a Contact by email. That is identification, not authentication. Anyone who knows an email could see its bookings. Real go-live needs OTP verification (the optional extension in your brief).

Flows

Flows are the simple readers and builders of data.

Search Packages autolaunched

Finds active packages that match the traveler’s wishes.

  1. If a destination was given: find the Destination by name, then its active packages. Otherwise: all active packages.
  2. Filter formula keeps those within budget, duration and type (blank inputs are ignored).
  3. A loop builds outPackageSummary text, which Recommend_Package reads.

Watch out: the first “Get Active Packages” lookup is never used (wasted query). Destination matches by exact name, so a misspelling likely returns nothing.

Verify Traveller autolaunched

  1. Find Contact by Email.
  2. Found: return verified = true, ContactId, FirstName.
  3. Not found: if email, first and last name are all present, create the Contact; otherwise verified = false.

Watch out: no fault path. If the duplicate-email rule blocks a create, the failure is not turned into a friendly message.

Find bookings autolaunched

Gets all Trip_Booking__c where Traveler__c equals the Contact ID. Privacy depends on that ID coming from Verify_Traveller, not being typed.

Seat release record-triggered

Runs after a booking is updated to Cancelled while Seats_Released is false (only when it newly meets that condition). Subtracts the booking’s travelers from the departure’s Booked Seats, then ticks Seats_Released so seats are never released twice.

Two routing flows routing

Inbound: sends new chats to the agent (routing type Copilot). Outbound: sends escalated chats to the Travel Support queue (QueueBased).

Apex

Apex handles money and seats because it gives you transactions, locking and strict validation.

CheckAvailabilityAndPrice read-only

  1. Validate: required fields, not in the past, at least 1 traveler, package active, within max travelers, valid price.
  2. Find the departure for that package and date.
  3. Seats left = Total minus Booked. Compare with travelers requested.
  4. If available: return price, total, departureId. If not: a clear message plus later departures with enough seats.

Your live chat said “no departure that day, try Nov 13 or Dec 13”. That’s this class working correctly.

CreateBooking writes data

  1. Locks the departure rows (FOR UPDATE) so two people can’t take the last seat.
  2. Re-validates seats at write time.
  3. Inserts the booking as In Process, adds travelers to Booked Seats.
  4. Savepoint and rollback: on any error, nothing is saved (“Booking failed. No seats reserved.”).

ModifyOrCancelBooking writes data

  • Checks the booking belongs to this traveler, status is In Process, seats not already released.
  • Cancel: subtract seats, status Cancelled, Seats_Released true.
  • Modify: new departure must be the same package, in the future, with room; then move seats old to new.
  • A failed new date leaves the old booking untouched.

Why Lists and Maps?

Salesforce can call these with many requests at once (bulkification). Collect IDs, run one query per object into a Map, then process. No queries inside loops, so no governor-limit errors.

Who releases seats?

SituationWho frees the seats
Traveler cancels via the agentModifyOrCancelBooking Apex (and it sets Seats_Released, so the Flow skips it)
Staff reject via approval / manual cancelThe Seat release Flow

LWC and the controller

These power the Experience Cloud website, separate from the chat agent.

CatalogController (Apex)

  • getDestinations: active destinations, A to Z. getPackages: active packages with destination name and highlights.
  • @AuraEnabled(cacheable=true) is required so LWCs can use @wire.
  • Class is without sharing, but getPackages uses WITH USER_MODE. That is inconsistent: pick one policy and give the guest profile read access to the objects and fields.

DestinationListing

@wire(getDestinations) fills a list. The template shows one of three states with lwc:if / elseif / else: loading, empty, or cards. On error it clears the list, stops loading and shows a toast.

PackageExplorer: a bug to fix

Same pattern, but isLoading is just packages === undefined. On error, packages is set to undefined, so the page shows “Loading packages…” forever.

Fix: add a separate isLoading boolean that turns false when the wire returns data or error, and an error message template.

Remember: for:each needs a unique key (the record Id). The brief wants loading, empty and error states in every component.

Mentor Q&A

Open each question, answer out loud first, then check.

Why did short replies go to Prompt Injection?

The classifier router judged each message alone. A date or “yes” has no intent by itself, so nothing matched and the guard topic caught it. Fix: a BookingFlowActive flag plus a context-aware model.

Why Flow, Apex and Prompt Builder?

Flow for simple lookups and assembling data. Apex for rules, math and safe multi-record writes. Prompt Builder for AI-written text (recommendation, summary, policy answer).

Why check availability twice?

The first check is a preview. Seats can vanish before the traveler confirms, so Create Booking re-checks inside a lock.

Do you really verify the traveler?

Only identify: lookup or create by email. It does not prove email ownership. Next step: OTP email verification.

How do you stop the AI inventing prices or policies?

Prices and seats come only from Apex and records. Policy answers come from a grounded template over the Data Library; if nothing is found the agent says it can’t confirm and offers human help. Citations are off so the PDF isn’t shown.

How does escalation work?

The escalation subagent calls @utils.escalate; the connection block routes to the Travel Support queue via an Omni-Channel routing flow. The agent never claims “you’re connected” until the platform confirms.

Why does SelectedDepartureId exist?

Create Booking needs a record ID, not “13 November”. Check Availability returns it only when seats exist; we store it so the booked departure is exactly the one checked.

What is the unused subagent?

ServiceCustomerVerification has no transition from the router. Verification happens inside the two booking subagents, so it is a leftover that can be deleted.

What would you improve?

OTP verification; fault paths and a friendly duplicate-email message; remove the redundant lookup and make destination matching tolerant; fix PackageExplorer’s error state; align the sharing policy; delete the unused subagent.

What’s in the brief but not in my files?

Approval process, scheduled flow for Trip Started and Completed, Planner Welcome LWC, Custom Lightning Type, the policy PDF and the Experience site pages. Be ready to show or explain these.
