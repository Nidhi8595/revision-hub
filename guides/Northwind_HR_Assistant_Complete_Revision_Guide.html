Northwind HR Assistant: revision guide

A retrieval-augmented chatbot over a sample employee handbook, built on Databricks: Unity Catalog, Delta, AI Search, a deployed agent and a Streamlit app.

Implemented and verifiedNeeds verificationRecommended improvementDiscrepancy note

The handbook is sample data. Its rules are not real company policy, and a working app does not make this production-ready.

1. Meet the project

An employee asks, “How many leave days can I carry over?” An ordinary LLM does not know Northwind’s handbook. RAG fixes that: search the handbook first, then give the best passages to the LLM so its answer is grounded in real text. Retrieval finds text; generation writes the answer. They are separate steps.

Traced example (verified in the PDF). Question → agent queries the index (“leave carry over policy”) → Annual Leave chunk returned → Llama 4 Maverick answers: up to 8 unused days, expiring March 31 (Section 1).

PDF_PATH = "/Volumes/hr_policy/hr_policy_data/hr_handbook_data/northwind_employee_handbook.pdf"
reader = PdfReader(PDF_PATH)
pages = []
for page_number, page in enumerate(reader.pages, start=1):
    text = page.extract_text() or ""
    pages.append({"page": page_number, "content": text})

enumerate(..., start=1) gives human page numbers. or "" turns None (an empty or scanned page) into an empty string so later code does not crash. Result: 2 pages. Always print a preview; scanned PDFs may need OCR.

4. Chunking and overlap

splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=100)
for page in pages:
    for n, content in enumerate(splitter.split_text(page["content"]), start=1):
        chunks.append({"id": f"page_{page['page']}_chunk_{n}", "content": content, "page": page["page"]})
chunk_sizeChunksObservation (PDF)
10033Sentences cut mid-rule (“expire on March”)
50002Whole sections together, less focused
500 / overlap 1006Chosen first as a balance
300 / overlap 4022 rows indexed after the second PDFTried later to improve retrieval

Sizes are in characters, not tokens. The test used chunk_overlap=min(100, size // 5) so tiny chunks keep a small overlap. Overlap repeats the tail of one chunk at the start of the next, so a rule that straddles a boundary still appears whole once.

Discrepancy. The PDF says the 300/40 change was needed for “more accurate results” but does not show a before/after comparison of answer quality. Treat the improvement as needs verification.

5. Store chunks in Delta

A Python list is gone when the notebook stops. A Spark DataFrame written as Delta becomes a governed, queryable table: hr_policy.hr_policy_data.handbook_chunks. Columns: id, content, page (and document after stretch goal 1).

# First run (verified): overwrite
chunks_df.write.format("delta").mode("overwrite").saveAsTable(TABLE_NAME)

# Later (verified): MERGE keyed on id
if spark.catalog.tableExists(TABLE_NAME):
    (DeltaTable.forName(spark, TABLE_NAME).alias("target")
       .merge(chunks_df.alias("source"), "target.id = source.id")
       .whenMatchedUpdateAll().whenNotMatchedInsertAll().execute())
else:
    chunks_df.write.format("delta").saveAsTable(TABLE_NAME)

Overwrite replaces everything. MERGE updates rows with matching ids and inserts new ones, so reruns do not duplicate rows. That only works if ids are unique and stable, which is why ids include the document name.

Heads up. If you change chunk size, old ids like page_1_chunk_6 may remain when the new run produces fewer chunks per page, because MERGE as shown never deletes. Check row counts. Needs verification against your table.

6. AI Search: endpoint vs index

Delta tableIndexEndpoint
IsSource rowsSearchable embeddingsCompute that serves queries
Namehandbook_chunkshandbook_chunks_indexgenai-rag-endpoint

Analogy: table = the book, index = the book’s searchable catalogue, endpoint = the librarian’s desk that answers. Creating hr-policy-search failed with a quota error (“exceeded quota of 3”), so the existing online Standard endpoint was reused.

Verified index settings: Hybrid, primary key id, compute embeddings from content, model databricks-gte-large-en, Triggered sync, status Online, 6 rows at first.

Triggered sync means the index updates only when you press Sync now (or run a sync). Saving rows to Delta does not by itself update the index. In the PDF, the second PDF reached 16 rows only after a sync; “Online” says the index is serving, not that results are relevant.

12. Troubleshooting playbook

Seen in the PDF Plausible, not recorded

CLI says refresh token invalid seen

Symptom: auth describe “Unable to authenticate”. Cause: expired login. Fix: databricks auth login --profile <name>. Verify: auth describe shows your user. Lesson: check auth before sync or deploy.

Cannot create AI Search endpoint seen

Symptom: quota exceeded. Fix: reuse an Online endpoint. Verify: index shows that endpoint.

Second PDF not retrieved seen as risk

Cause: Delta updated but triggered index not synced. Fix: Sync now. Verify: rows indexed rises (6 → 16) and a SQL vector_search returns the new document.

Wrong top result seen

Sick leave outranked parental leave. Check all top results, tune chunking, test more questions. Do not trust rank 1 alone.

App cannot reach endpoint plausible

Check: endpoint Ready, app resource with Can query, endpoint name exact. Lesson: permissions and readiness are separate checks.

Env var missing plausible

os.environ["VECTOR_SEARCH_INDEX"] raises KeyError if the resource key or valueFrom does not match. Fix the key, redeploy.

Source panel fails but answer works plausible

Likely missing Can select on the index, or a wrong column name. The try/except is why the answer still appears.

13. Improvements and interview prep

Not implemented Systematic retrieval tests with expected answers; compare 300/40 vs 500/100 with measured results; show the agent’s actual retrieved chunks instead of a second query; handle updated or removed chunks; log latency and cost; define who may use the app and what the agent can access before any real HR use.

Why RAG instead of asking an LLM directly?

The LLM has never seen the handbook. RAG supplies the relevant text at question time and lets the answer be checked against sources. Follow-up, can it still hallucinate? Yes; instructions reduce it, they do not eliminate it.

Table vs index vs endpoint?

Table stores rows, index stores searchable embeddings built from them, endpoint is the compute that serves the index. Follow-up, why must you sync? Triggered mode only updates on request.

How does it handle out-of-scope questions?

Retrieval still returns nearest chunks. The system prompt tells the LLM to say it cannot find the answer. Follow-up, how would you test it? A set of out-of-scope questions with expected refusals.

Agent vs serving endpoint?

The agent is code plus a registered model version. The endpoint is the running service that hosts that version. The app calls the endpoint.

What must change for production?

Evaluation, monitoring, access control review, update process, real policy ownership, and a tested deployment pipeline.
